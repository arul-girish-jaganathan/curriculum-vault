# Extract and insert

> Canonical C topic note — Chapter 43. Bit-field extraction and insertion convert between packed integer representations and logical fields. Correct code must define field width, position, masks, and overflow policy.

## Definition
To extract a field, shift the desired bits down and mask them. To insert, clear the destination field and OR in a bounded value shifted into position. This is preferable to implementation-dependent C bit-fields when a stable binary representation is required.

## Mechanism and language rules
For an unsigned word `x`, a typical extraction is `(x >> pos) & mask`. Insertion is `(x & ~(mask << pos)) | ((value & mask) << pos)`. Every shift count must be valid for the promoted operand width.

### What to reason about
- Is `mask` expressed in field bits or word bits?
- Is `value` validated or intentionally truncated?
- Can `mask << pos` overflow the intended type?
- Is the serialized representation required to be endian-independent?
- Is the field signed and does it require sign extension?

## Embedded implications
Packed fields are common in registers, network packets, EEPROM records, and protocol headers. Explicit shifts and masks make the bit numbering visible and avoid compiler-dependent layout of C bit-fields.

### Firmware review angle
For protocols, define the wire bit numbering and byte order separately. A 16-bit field at bits 4–7 is not enough information unless the byte ordering of the containing word is also specified.

## Edge cases and failure modes
- Field width zero or larger than the word.
- Position plus width exceeds the word size.
- Signed values are shifted unexpectedly.
- Insertion silently truncates a value that does not fit.
- Host integer representation is incorrectly assumed to equal wire representation.

## Example pattern
```c
#define FIELD_MASK  UINT32_C(0x0f)
#define FIELD_SHIFT 8U

uint32_t get_field(uint32_t x)
{
    return (x >> FIELD_SHIFT) & FIELD_MASK;
}

uint32_t put_field(uint32_t x, uint32_t value)
{
    x &= ~(FIELD_MASK << FIELD_SHIFT);
    x |= (value & FIELD_MASK) << FIELD_SHIFT;
    return x;
}
```
The mask documents that only four bits are represented.

## Verification / debugging
Test zero, maximum representable value, one-above-maximum, adjacent fields, and highest-position fields. Round-trip test `put_field(get_field(...))` with known patterns. Compare generated bytes against protocol specifications.

## Staff-level takeaway
Treat extraction/insertion as a **representation boundary**. Explicitly define width, position, truncation, signedness, and byte order rather than relying on visual intuition about packed integers.
