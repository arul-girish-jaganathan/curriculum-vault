# Debugging Obsidian Knowledge Base

## Structure
90 canonical debugging chapters, each with 12 focused concept notes and a chapter index.

## Intended use
Use `00_Complete_Topic_Map.md` as the navigation surface. Treat each topic note as canonical knowledge; link projects, interview notes, mistakes, and postmortems to these concepts rather than duplicating them.

## Depth standard
Each concept should ultimately explain mechanism, evidence, reproduction, tooling, failure modes, edge cases, embedded/system consequences, performance/observer effect, prevention, and Staff-level reasoning.

## Suggested Obsidian usage
1. Extract this folder into your vault.
2. Open `00_Complete_Topic_Map.md`.
3. Enable backlinks and graph view.
4. Add project-specific evidence under your existing `02_Projects/` area and link back to canonical concepts.
